# A–C. Архитектура системы

## Главная идея

```
CRM                      = операционка: карточки клиентов, телефоны, переписка, детальная история
Google-система (Sheets)  = управленческий слой по объекту:
                           СТРАТЕГИЯ → ПЛАН → ДЕЙСТВИЯ → РЕЗУЛЬТАТ → КОНВЕРСИЯ → ВЫВОД → СЛЕДУЮЩИЙ ШАГ
Отчёт клиенту (Doc+PDF)  = автоматически собранный результат этой работы
```

Каждый факт вводится **один раз** и в **одном месте**. Всё остальное — формулы и скрипт.

| Что происходит | Куда вводится | Что считается само |
|---|---|---|
| Взяли объект | 01_ОБЪЕКТЫ (1 строка, ID из CRM) | проверка ID, цена за м², дни в продаже, строка в 02, флаг риска |
| Определили стратегию | 02_СТРАТЕГИЯ (кратко) + Google Doc (подробно) | дата изменения, кто изменил, история правок, «дней с пересмотра» |
| Сделали что-то по продаже | 03_ДЕЙСТВИЯ (1 строка = 1 действие) | неделя, «последнее действие» и «дни без активности» в 01, статистика, факт KPI в 06, отчёт |
| Появился покупатель | 04_ЛИДЫ (1 строка = 1 лид) | этапы воронки по статусу, конверсии, дата сделки |
| Планируем неделю | 06_ПЛАН_ФАКТ (меню «Создать план недели») | факт KPI, % выполнения, просрочки, перенос задач |
| Пятница | 07_ОТЧЕТ: выбрать объект и неделю → «Создать отчёт» | Google Doc, PDF, запись в архив, ссылка в 01 |

## C. Список листов

| Лист | Роль | Ввод |
|---|---|---|
| **01_ОБЪЕКТЫ** | Реестр эксклюзивов, 1 строка = 1 объект | вручную + формулы |
| **02_СТРАТЕГИЯ** | Краткая управленческая стратегия + ссылка на Google Doc | вручную |
| **03_ДЕЙСТВИЯ** | Главный журнал: 1 строка = 1 действие, все каналы в одном месте | вручную или форма «Добавить действие» |
| **04_ЛИДЫ_И_КОНВЕРСИИ** | Воронка: 1 строка = 1 лид; справа — блок конверсий с фильтрами | вручную |
| **05_СТАТИСТИКА** | Итого / по каналам / по объектам / по месяцам / по неделям | только фильтр |
| **06_ПЛАН_ФАКТ** | План недели; справа — % выполнения и план/факт по KPI | вручную + меню |
| **07_ОТЧЕТ** | Динамический шаблон отчёта (предпросмотр того, что увидит клиент) | выбор объекта/недели + комментарий |
| **08_СПРАВОЧНИКИ** | Все выпадающие списки + системные классы статусов + недели | вручную (списки) |
| **09_ДЭШБОРД** | Управленческая картина, неделя, конверсии, предупреждения, объекты, график | только выбор недели |
| **10_НАСТРОЙКИ** | Пороги X (дни без активности и т.д.), подпись отчёта, KPI по умолчанию, служебные ID | вручную |
| **11_КОНТРОЛЬ** ➕ | Все предупреждения одним списком + мониторинг по объектам | нет |
| **12_ИСТОРИЯ** ➕ | Журнал изменений: цены, статусы, стратегия, переносы задач | только скрипт |
| **13_АРХИВ_ОТЧЕТОВ** ➕ | Реестр всех отчётов: Doc, PDF, кто и когда создал, версия | только скрипт |

➕ — листы сверх минимального списка ТЗ. Они не меняют логику ТЗ, а реализуют его требования:
п.12 «автоматические предупреждения» (11), п.18 «история, старая цена остаётся» (12), п.10 «хранить историю всех отчётов» (13).

## B. Схема связей

```
                         08_СПРАВОЧНИКИ ──(выпадающие списки, классы статусов, недели)──► все листы
                         10_НАСТРОЙКИ ──(пороги CFG_*)──► 01, 11, 09, условное форматирование

 01_ОБЪЕКТЫ ◄──────────── ID объекта из CRM ────────────────────────────────────┐
   │  1                                                                        │
   ├──1:1──► 02_СТРАТЕГИЯ ──► Google Doc стратегии (01_STRATEGIES/<объект>)    │
   ├──1:N──► 03_ДЕЙСТВИЯ  (ACT-0001)  ── неделя из даты ──┐                    │
   ├──1:N──► 04_ЛИДЫ      (LEAD-0001) ── неделя из даты ──┤                    │
   ├──1:N──► 06_ПЛАН_ФАКТ (TASK-0001) ── неделя (ключ) ───┤                    │
   └──1:N──► 13_АРХИВ_ОТЧЕТОВ ──► Google Doc + PDF (02_WEEKLY_REPORTS/<объект>)│
                                                          ▼                    │
                     05_СТАТИСТИКА, 07_ОТЧЕТ, 09_ДЭШБОРД, 11_КОНТРОЛЬ ─────────┘
                     (читают 03/04/06 по ключам «ID объекта» + «Неделя»)
 12_ИСТОРИЯ ◄── onEdit: изменения 01 (цена, статус…), 02 (все поля), 04 (статус), 06 (статус, дедлайн, план)
```

**CRM.** У CRM нет API, поэтому интеграции нет и не планируется: объекты и адреса заводятся в 01_ОБЪЕКТЫ вручную. Система — инструмент маркетинговой стратегии и управления продажей объекта, а не замена CRM.

**Ключи.** Все связи — только через ID. **ID объекта берётся из CRM и вводится вручную** в 01_ОБЪЕКТЫ — так объект легко найти в CRM по тому же номеру. Скрипт проверяет, что ID заполнен и не повторяется (столбец «Проверка ID», предупреждение в 11_КОНТРОЛЬ), а если ID исправить в 01, он сам заменится во всех связанных строках 02/03/04/06/13 и в названиях папок Drive. ID действий, лидов и задач (`ACT-0001`, `LEAD-0001`, `TASK-0001`) ставит скрипт — в CRM их нет. Название объекта ключом не является: его можно переименовать, связи не порвутся. Поле «Ссылка на CRM» — просто ссылка на карточку, чтобы не переносить данные.

**Неделя.** Единый ключ — ISO-неделя `2026-W39`. В 03 и 04 она считается из даты формулой, в 06 выбирается из списка. Человеческая подпись — `2026-W39 · 21.09–27.09.2026` (справочник «Недели» в 08, в выпадающих списках 07 и 09). Неделя = понедельник–воскресенье.

## Откуда берётся каждый показатель

Важное методическое решение (прошу подтвердить, см. раздел «Предложения» ниже):

| Показатель | Источник | Смысл |
|---|---|---|
| Действия | 03, строки со статусом класса DONE | сколько выполнено действий |
| Контакты, ответы, заинтересованные, презентации, показы, повторные контакты, предложения, переговоры, брони, сделки | 03, суммы счётчиков | **события** за период (5 показов = 5 показов, даже если это 2 покупателя) |
| Лиды | 04, по дате первого контакта | новые уникальные покупатели |
| Квалифицированные лиды | 04, галочка «Квалифицирован» | уникальные |
| Воронка уникальных лидов (блок справа в 04) | 04, галочки этапов | сколько **людей** дошло до этапа |
| Просмотры объявлений / контакты по объявлениям | 03, каналы с флагом «Площадка объявлений = ДА» (08) | эффективность ЦИАН/Авито/Яндекс |
| Стоимость лида | 03 «Расходы» / 04 лиды | |
| Дни на рынке, дни без активности | 01 (формулы от дат) | |
| Динамика цены | 12_ИСТОРИЯ (первая цена vs текущая, число изменений) | |
| Дни лид → сделка | 04 (дата сделки ставится скриптом при статусе «Сделка») | |
| Факт KPI в плане недели | 03/04 по объекту+неделе (+тип действия, если указан) | вводить факт KPI вручную не нужно |

## Что идёт клиенту, что остаётся внутри

Отчёт собирается **только** из строк листа 07 с placeholder'ами. В них попадают:
- 03: дата, тип, канал, «Факт» (или «Цель», если факт пуст), «Обратная связь», «Вывод», «Причина отказа», «Следующий шаг» — только у действий с галочкой **«В отчёт клиенту»** и статусом «Выполнено»;
- 03/04: числа (контакты, ответы, лиды, показы…);
- 06: задачи и KPI **следующей** недели, «Вывод» задач (с галочкой «В отчёт клиенту»);
- 12: изменения цены и только тех полей стратегии, которые перечислены в 08 → «Поля стратегии, видимые клиенту» (позиционирование, ключевой аргумент, каналы, партнёрские каналы, контент-стратегия, план продвижения, вывод);
- 07: «Комментарий руководителя для клиента» (пишется перед созданием отчёта).

**Никогда не попадают:** комментарии (03, 04, 01 «Комментарий руководителя»), расходы, бюджеты и имена лидов, причины потери, причины невыполнения задач, целевая цена и ценовой диапазон, слабые стороны, «что нельзя использовать публично», гипотезы, статусы задач, % выполнения плана, флаги риска. На листе 07 они видны в блоке «ВНУТРЕННЕЕ» — для вас, не для клиента.

## Масштабирование (п.25 ТЗ)

- Все формулы журналов — одна ARRAYFORMULA в заголовке на весь столбец; диапазоны открытые (`$B$2:$B`), фиксированных `A2:A15` нет.
- Списки объектов, недель, каналов в 05/07/09/11 строятся формулами `FILTER/UNIQUE` — новый объект появляется везде сам (это проверяет самопроверка «Масштаб»).
- Лимиты раскладки 05_СТАТИСТИКА: до 60 каналов и до 200 объектов в секциях (раздел «по неделям» не ограничен). При 30–50 объектах запас четырёхкратный.
- Журналы созданы на 2000 строк; «Обновить статистику» сама добавляет по 1000 строк, когда остаётся меньше 200 свободных, и растягивает на них списки и галочки.

## Отступления от ТЗ и предложения

### Уже сделано (дополнения, логику ТЗ не меняют)
1. Листы 11_КОНТРОЛЬ, 12_ИСТОРИЯ, 13_АРХИВ_ОТЧЕТОВ — см. выше.
2. **KPI в 06 разбит на «KPI» (метрика из списка) + «KPI план»**, а «Фактический KPI» считается сам. Иначе план/факт по контактам, лидам и т.д. нельзя посчитать без ручного ввода.
3. Галочки **«В отчёт клиенту»** в 03 и 06 — управляемый способ не показать клиенту внутреннее действие.
4. В 03 добавлены «Просмотры (охват)» и «Расходы, ₽» — без них не посчитать конверсию объявления и стоимость лида (оба показателя есть в ТЗ). В 04 — «Квалифицирован» (галочка), «Ссылка на CRM», «Дата сделки».
5. В 06 — «ID задачи», «Перенесено из», «Просрочка»: так перенос не стирает старый план (п.18).
6. В 02 — «Статус стратегии» (утверждение руководителем, п.14), «Требуется изменение стратегии», «Дата последнего изменения», «Кто изменил».
7. В шаблоне отчёта дополнительно: `{{CHANNELS}} {{INTERESTED}} {{PRESENTATIONS}} {{DEALS}} {{OBJECTIONS}} {{STRATEGY_CHANGES}}` и подпись `{{MANAGER_NAME}} {{MANAGER_CONTACT}} {{AGENCY}} {{REPORT_DATE}}` — пункты 5, 15, 17 списка содержимого отчёта из ТЗ не имели своих placeholder'ов.
8. В списке типов действий ТЗ «Telegram» указан дважды — оставлен один.

### Предлагаю, но НЕ внедрял — нужно ваше решение
1. **Два источника чисел воронки.** Сейчас показы/переговоры/брони в статистике и отчёте — это *события* из 03, а в блоке воронки 04 — *уникальные лиды*. Это честнее для отчёта («провели 3 показа»), но цифры в 04 и 05 могут не совпадать. Альтернатива — считать всё только по лидам (меньше ручного ввода счётчиков, но теряется «повторный показ тому же человеку»). *Влияние:* при переходе ассистенту не нужно будет заполнять счётчики показов/переговоров в 03 — только статус лида.
2. **Одна папка на объект** (`04_OBJECTS/Остров/{Стратегия, Отчёты, Материалы}`) вместо раздельных `01_STRATEGIES/Остров` и `02_WEEKLY_REPORTS/Остров`. *Почему:* всё по объекту в одном месте, одна ссылка «папка объекта». *Влияние:* меньше переходов; но структура отличается от ТЗ, поэтому не менял.
3. **«Дата закрытия» у объекта.** Сейчас «дни в продаже» у проданного объекта продолжают расти. Предлагаю поле, которое ставится при статусе «Продан/Снят», и счёт дней до него. *Влияние:* +1 автоматическое поле, ручного ввода нет.
4. **Форма «Добавить лид»** по аналогии с «Добавить действие». *Влияние:* ассистент вводит лида из одного окна.
